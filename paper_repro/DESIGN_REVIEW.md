# 실행 전 설계 검토 — v3에 반영한 변경과 남은 한계

2026-11-10. 사용자가 실험 #3 본실험이 전혀 실행되지 않았다고 확인했다. 이전에 후속 제안으로 남긴 개선 사항을 **현재 설계와 코드에 반영**했다. 활성 기준은 `PREREG.md`, 변경 전 기준은 `PREREG_v1_archive.md`다. 새 GPU 결과는 생성하지 않았다.

## 왜 이미지 내 위치 분할 대신 클래스 분할인가

현재 HF 데이터에는 손상 간 같은 원본 이미지의 식별자가 명시적으로 검증되지 않았다. 클래스 내 ‘몇 번째 이미지’가 모든 손상에서 같은 원본이라고 가정해 20/30장으로 나누면 누수가 남을 수 있다. 클래스 분할은 그 가정 없이 역할 간 이미지 중복을 막는다. 다만 이것은 **새로운 클래스 분포로의 전이**라는 더 어려운 질문을 만든다. 따라서 논문 재현 수치와 혼합하지 않고 역할별 클래스 목록과 zero-shot 성능을 공개한다.

## 개발 세트를 추가하지 않은 이유

이번 v3는 신호·방향·예산·lookback·전환 정책을 지금 고정한다. 개발 결과로 선택할 하이퍼파라미터가 없으므로 별도 개발 스트림을 추가하지 않았다. 확인 결과를 본 뒤 신호를 선택하거나 규칙을 바꾸려면 v3 결과를 탐색으로 전환하고 새 확인 세트를 사전등록해야 한다.

## 남아 있는 한계

1. **seed 간 같은 이미지 재사용**: 순서 seed10개는 독립 이미지 데이터셋10개가 아니다. bootstrap은 고정 이미지 풀의 순서 민감도에 대한 기술적 구간으로만 보고한다. 배포 빈도 추정에는 별도 이미지 풀·데이터셋이 필요하다.
2. **보정에서 확인으로 클래스 분포 이동**: 명목5%가 실제5%를 보장하지 않는다. 모든 신호의 실제 오경보를 함께 보고하고, 예산이 다른 신호의 지연만 비교해 우월성을 주장하지 않는다.
3. **보정 자체가 오염될 수 있음**: 정답으로 정제하지 않으므로 보정에서도 TTA가 해로울 수 있다. 이는 정직한 무라벨 절차의 한계이며, 낮은 감지율을 보고 임계값을 다시 고르지 않는다.
4. **논문에 기반한 조합 선택**: 손해가 큰 후보를 의도적으로 골랐다. 존재 사례와 정책 효용의 확인이지 모든 TTA 설정의 발생 확률 표본이 아니다.
5. **WebP와 세 손상**: 원본 JPEG 재현이나 15개 전체 평균이 아니다. 불일치 원인을 방법의 실패라고 단정하지 않는다.
6. **512장 시간 해상도**: 사건은 사후3구간 지속으로 정의되고 신호도 구간 끝에만 사용 가능하다. 늦은 경보와 최악 구간 손해를 숨기지 않는다.
7. **transductive TTA**: 논문 방법은 같은 배치를 적응과 예측에 사용한다. 엄격한 다음 샘플 사전 예측/실시간 처리 성능으로 해석하지 않는다.
8. **shadow 정책 평가**: 첫 전환 후 모델을 복귀시키지 않으므로 오프라인 재생이 정확히 가능하다. 복귀 정책이나 계산 절약의 검증은 아니다.
9. **작은/선택된 조합 집합과 계산 예산**: 확인10회는 검정력 분석 결과가 아니다. 조합당117만 장, 전체468만 장이 필요하다. 자원 부족을 이유로 좋은 결과만 남기지 말고 미완료를 명시한다.

## 실행 전 남은 환경 검증

CPU 회귀와 합성 결과를 이용한 전체 파이프라인은 연구 효과의 증거가 아니다. 실제 pinned CUDA 환경에서 모델 로드·데이터 접근·역할별 완결성·무중단/재개 동등성을 검증해야 한다. 현재 클라우드의 HF 메타데이터 접근은 프록시 터널403으로 실패했고 CUDA GPU가 없다. Colab/허용된 네트워크에서 검증해야 하며, 이를 이미 실행한 것으로 기록하지 않는다.
