# 실험 #3 사전등록 v3 — 실행 전 개정

개정일: 2026-11-10 (Asia/Seoul).
사용자가 이 실험의 본실험을 아직 전혀 실행하지 않았다고 확인했다. 따라서 이번 변경은 실험 #3 결과를 본 뒤의 기준 변경이 아니라 **실행 전 설계 변경**이다. 이전 버전은 `PREREG_v1_archive.md`에 보존한다. 이 문서와 코드를 커밋하고, 첫 실행 전에 데이터 revision과 실행 계획을 고정한다. 과거 탐색 실험의 로그는 이미 존재하지만 이번 확인 실험의 결과는 아니다.

## 1. 질문과 주장 범위

1. 논문 기준 설정에서 zero-shot보다 해로운 TTA 사례가 나오는가? (`paper` 기준 실행)
2. 정답으로 구간을 선별하지 않고 보정한 신호가 별도 클래스의 손해 사건을 감지하는가? (`calibration` → `confirmation`)
3. 경보 후 다음 배치부터 zero-shot으로 전환하면 같은 스트림에서 누적 손해를 줄이는가? (사전 고정한 전환 정책)

주장은 고정된 ImageNet-C 이미지·클래스 집합에서의 스트림 순서 변동에 한정한다. seed별 실행은 서로 다른 배포 데이터셋이 아니다. 실제 배포 손해의 발생 확률이나 보편적인 무라벨 안전성을 주장하지 않는다.

## 2. 사전 고정 조합과 실행량

| ID | 방법 | 모델 | 사전 역할 |
|---|---|---|---|
| A | ETA | ViT-L/14 | 논문 기준 조합 |
| B1 | ETA | ViT-B/16 | 비교적 저렴한 큰 손해 후보 |
| B2 | Tent | ViT-B/16 | 예측 집중/붕괴 대조군 |
| B3 | SAR | ViT-L/14 | 낮은 예측 집중도의 손해 후보 |

각 조합을 따로 분석하며 결과 유무와 관계없이 네 조합을 모두 보고한다. 실행 순서는 B1 → B2 → A → B3. 자원 때문에 중단되면 미실행 조합과 seed를 명시하고, 완료된 실행만으로 전체 계획 완료를 주장하지 않는다.

각 조합은 `paper` seed 1, 보정 seed **101·102**, 확인 seed **201–210**을 실행한다. 확인 결과를 보고 seed·조합·기준을 교체하지 않는다. 확인 10개가 모이기 전에는 최종 요약을 만들지 않는다. 10개는 계산 예산에 따른 고정 확인 횟수이며 검정력을 보장하지 않는다.

주 데이터는 severity 5의 gaussian_noise·shot_noise·impulse_noise 세 개로 고정한다. 15개 논문 평균과 비교하지 않는다. 15개 재현을 추가하면 별도 출력 루트와 분석 범위로 보고한다.

조합당 처리량: 기준 150,000장 + 보정 60,000장×2 + 확인 90,000장×10 = **1,170,000장**, 네 조합 총 **4,680,000장**. zero-shot과 TTA 계산이 모두 필요하다. 실행 전 스모크/처리량 측정으로 시간을 추정하되, 결과에 따라 계획 일부만 선별하지 않는다.

## 3. 데이터·스트림·모델 고정

- HF `haideraltahan/wds_imagenetc`의 **40자리 commit SHA**를 첫 실행 계획에 저장한다. 모든 다운로드는 해당 revision URL을 사용한다. WebP 재인코딩 데이터이므로 원본 JPEG와의 엄밀한 픽셀 재현은 아니다.
- 논문 코드 커밋 `8b2ed63`, Python 3.11, torch 2.2.1, open_clip 2.24.0, OpenAI 가중치, Radford 80개 프롬프트, 배치 64, 논문 방법별 기본 설정을 유지한다.
- 실제 optimizer param group의 LR을 기록한다. 특히 upstream SAR는 ViT에서 0.001을 사용하므로 cfg의 LR만 보고하지 않는다.
- `paper`: 클래스 1000개 전부, 클래스 번호 순서, 클래스 내 50장만 seed로 섞음. 손상은 논문 순서. domain 사이 초기화 없음.
- 주 감지 실험: seed **1729**로 전체 클래스 목록을 한 번 섞고 앞 400개를 보정, 뒤 600개를 확인에 배정한다. 각 클래스의 50장을 모두 사용한다. 두 역할은 클래스와 이미지가 겹치지 않으며, 손상 버전이 달라도 동일 이미지가 양쪽에 들어갈 수 없다.
- 클래스 블록 순서와 세 손상 순서는 각 실행 seed로 무작위화한다. 각 역할 내에서는 같은 이미지가 seed별로 재사용된다. 보정/확인 클래스 분포가 다르다는 일반화 부담을 숨기지 않는다.
- 원본 split 내 sample ID와 클래스 목록·domain 순서·코드 해시·설정·라이브러리 버전을 기록한다. 클래스 ID는 고정된 1000-way 분류기 라벨이며 역할별로 재번호를 매기지 않는다.
- 한 클래스의 압축 이미지 블록만 메모리에 두고, 클래스 순서 재배열에는 임시 디스크를 쓴다. 다운로드 실패를 데이터 제외로 처리하지 않는다.
- gradient checkpointing은 조합별 첫 실행 전에 고정하고 역할/seed 사이에 바꾸지 않는다. 수치 동등성을 가정하지 않는다.
- 논문 방식의 같은 배치 기반 transductive TTA를 유지한다. 엄격한 다음 샘플 예측 실험으로 해석하지 않는다. 두 모델은 같은 이미지를 입력받는다.

## 4. 정답 없는 임계값 보정과 동결

- 보정 실행 101·102를 모두 끝낸 후 **각 실행의 처음 100개 완전한 512장 구간**을 사용한다. 정답·정확도·손해 여부로 구간을 선별하지 않는다. 보정 구간에도 손해가 있을 수 있다.
- 100구간이 없거나 신호가 누락되면 실패로 중단한다. 표본 부족을 이유로 오경보 예산을 10%로 올리지 않는다.
- 주 신호: TTA와 zero-shot의 **disagreement rate**, 위쪽 꼬리.
- 주 비교 신호: TTA entropy(양쪽), zero-shot entropy(양쪽), 알려진 전체 스트림 길이 대비 진행률(위쪽). KL(위쪽)·top-5 일치율(아래쪽)은 탐색이다.
- 모든 신호의 명목 구간당 오경보 예산은 **5%**. 한쪽 꼬리는 95% 또는 5% 분위수, 양쪽 꼬리는 2.5/97.5% 분위수. 경계와 같으면 경보를 울리지 않는다.
- 이 예산은 보정 분포의 경험적 분위수다. 시간 의존성과 클래스 분포 이동 때문에 확인 실행의 실제 5%를 보장하지 않는다. 실제 오경보율을 반드시 보고한다.
- 기준값, 보정 결과 파일 해시, 데이터/코드/설정 signature를 `*_calibration.json`에 기록한다. 파일이 이미 있으면 덮어쓰지 않는다. **동결 파일이 생기기 전에 확인 실행을 시작하지 않는다.**
- 확인 실행에서 임계값을 재보정하지 않는다. 신호 방향·꼬리·주 신호·예산을 결과를 보고 변경하지 않는다.

## 5. 손해 사건과 유형 (평가에만 정답 사용)

- 전체 실행을 이어서 512장씩 자른다. 마지막 미완성 구간은 사건/경보 집계에서 제외하지만 전체 정확도에는 포함한다.
- Δ = TTA 정확도 − zero-shot 정확도. Δ ≤ −5%p인 구간이 3개 이상 연속이면 손해 사건. 정답은 사건/유형/성능 평가에만 사용한다.
- 주 유형: 사건 구간들의 `TTA 최빈 비율 / 정답 최빈 비율` 평균이 ≥4면 붕괴, ≤1.5면 낮은 예측 집중도의 손해(기존 명칭 ‘조용한 손해’), 사이는 별도.
- absolute 50%/10% 기준은 민감도 분석으로만 보고한다. 낮은 예측 집중도는 안정성이나 올바른 클래스 분포를 뜻하지 않는다.
- B3 Δ ≤ −3%p, 다른 창 크기, 다른 임계값은 주 확인 결과에 포함하지 않는다. 필요하면 새로운 탐색 결과로 명시한다.
- `paper`의 seed 1 결과는 기준 사례이며, 개선된 주 실험의 확인 빈도에 섞지 않는다. 이전의 ‘새 seed 2/3 통과’ 이진 판정은 주 감지 실험에서 폐기한다.

## 6. 경보 시간과 오경보

- 구간 i 신호는 **(i+1)×512번째 샘플을 처리한 후** 사용할 수 있다. 구간 시작에 경보가 이미 있었다고 취급하지 않는다.
- 사건 시작 전 **2구간 lookback**부터 사건 끝까지 발생한 **새 경보 시작점**만 해당 사건의 감지로 인정한다. 더 오래전부터 계속 켜져 있던 경보는 소급 성공으로 세지 않는다.
- 사건 시작 대비 sample 지연과 세 번째 손해 구간 끝(사건 확인 시점) 대비 지연을 모두 기록한다. lookback에서 잠깐 울렸다 꺼진 경보도 이 범위 내 예측 경보로 집계되지만, 그 비손해 부분은 오경보에도 포함한다.
- 사건 감지율·미감지 수·미감지를 +∞로 포함한 상위 중앙 지연을 함께 보고한다. 사건이 없으면 감지율은 판정 불가이며 0/0을 성공으로 보지 않는다.
- 비손해 구간의 실제 경보 비율과 비손해 10,000장당 오경보 묶음 수를 함께 보고한다. 실제 예산을 초과한 신호를 같은 예산에서 더 우수하다고 주장하지 않는다.
- 주 비교는 같은 확인 실행에서 각 신호의 지연/미감지/오경보를 나란히 제시한다. 명목 예산만 같다는 이유로 실제 오경보율 차이를 무시한 ‘통과’를 출력하지 않는다.

## 7. 전환 정책과 주 결과

배포 가능성의 주 결과는 주 신호로 동결한 임계값을 적용한 **zero-shot 대비 누적 정확도 차이**다.

- 항상 zero-shot / 항상 TTA / 첫 disagreement 경보 후 다음 배치부터 영구 zero-shot 전환 / 정답 기반 batch oracle 상한을 동일 샘플에서 비교한다.
- 보정과 확인은 모델을 새로 초기화한 별도 실행이다. 확인 실행에는 라벨을 이용한 준비/전환이 없다.
- 전환은 구간 끝 이후 첫 배치부터 적용한다. 같은 구간의 예측을 소급해서 바꾸지 않는다. 이번 정책은 복귀·쿨다운이 없다.
- 실제 기록은 shadow TTA를 계속 실행한다. 정책은 첫 전환 이전의 TTA와 이후의 zero-shot만 쓰므로 이후 TTA 업데이트는 정책 성능에 영향을 주지 않는다. 이 방식으로 계산량 절약이나 실시간 지연 개선을 주장하지 않는다.
- 조합별 10개 확인 실행의 정책 Δ 평균, 최악 512장 구간 Δ, seed별 원시 수치를 보고한다. run 단위 bootstrap 2000회(seed1729)의 95% 구간은 **고정 이미지 집합의 순서 변동**에 대한 기술적 불확실성이다. 독립 데이터셋 일반화의 신뢰구간이 아니다.
- 네 조합 중 좋은 것만 선택하거나 조합 간 합산으로 성공을 만들지 않는다. 다중 비교에 대한 통계적 유의성 주장은 하지 않는다.

## 8. 실행·중단 규칙

`run_plan.py`가 조합별 계획을 저장하고 `paper → calibration → freeze → confirmation → evaluate` 순서를 실행한다. 조합별 첫 GPU 실행 전에 계획 파일에 데이터 revision·코드 해시·checkpointing을 저장한다. 이후 코드/설정이 바뀌면 같은 출력 루트에서 재개하지 않는다.

스모크와 CPU 회귀 테스트는 환경/구현 검증이며 연구 결과가 아니다. GPU 무중단/재개 동등성 검증도 본실험과 다른 출력 루트에서 수행한다. 실패한 조합·미완료 seed·데이터 접근 실패를 누락하지 않는다.

실행 안내: `VALIDATION.md`. 변경 이유와 남은 한계: `DESIGN_REVIEW.md`.
